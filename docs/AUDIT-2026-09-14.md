# Workflow audit — 14 September 2026

## Verified findings and fixes

- The hosted Supabase project was inactive and its hostname did not resolve. Signup and notification browser journeys failed before authentication. The existing project was resumed through the Management API and verified ACTIVE_HEALTHY. The forward migration was applied; the subsequent migration dry run reported the remote database up to date.
- Account-wide Agent proposals conflicted with the conversation-Workspace target trigger. A forward migration adds an independently validated destination Workspace while preserving conversation attribution. Approval cards disclose that destination.
- Agent ignored persistence errors. Answer, proposals, steps, and final run state now save in one database transaction. Context read failures and invalid targets fail explicitly; failed runs are linked to the saved user message and their details remain visible. Redacted diagnostics distinguish context, persistence, structured-output, and provider-timeout failures.
- Approvals previously used separate writes for claiming, mutation, activity, and completion. A locked transaction now applies all four supported tools atomically, rechecks owner and destination, rejects archived targets, expires seven-day-old proposals, and completes runs after their last decision. Repeated approval is idempotent; a failed mutation rolls back and remains retryable.
- Compatible-provider URL validation allowed IPv6 loopback, URL credentials, and nonstandard ports. Requests now check DNS results and private addresses, reject credentialed/nonstandard endpoints, and disallow redirects. The shared address check recognizes hexadecimal IPv4-mapped IPv6. Existing DNS-check/fetch separation is retained; this is not a claim of transport-level DNS pinning.

- Password recovery ignored Supabase errors and falsely reported success. It now distinguishes rejected requests, verifies recovery/invitation token hashes, and converts implicit invitation sessions into SSR cookies before showing the password form. One-time recovery, actual password update, expired-link rejection, and implicit invitation handling passed browser tests.
- Account deletion omitted CAPTCHA from password reauthentication. The dialog now presents the existing verification widget, passes its token, preserves the account on verification failure, reports the correct error, and signs out after successful deletion.
- The selected OpenRouter Nemotron free model advertises tool calls rather than JSON-schema response format. A real tiny tool response took 73 seconds, exceeding the old 45-second timeout. OpenRouter now uses validated forced-tool output with bounded output tokens and reasoning disabled; requests have a 120-second timeout and AI pages allow 180 seconds. The real connection test passed.

## Development and release workflow
